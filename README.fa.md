# ESBot — CRM و خدمات پس از فروش

نسخهٔ **MVP عملیاتی نسخه 0.3.0** با رابط فارسی RTL، بک‌اند FastAPI، پایگاه داده SQLAlchemy و ربات بله با long polling. این نسخه برای اجرای محلی و آزمایش جریان‌های اصلی ساخته شده و نباید بدون بازبینی امنیتی/عملیاتی برای داده‌های حساس یا ارسال انبوه در محیط تولید استفاده شود.

## قابلیت‌های پیاده‌سازی‌شده

- ورود مدیر با رمز هش‌شده و توکن JWT
- داشبورد متصل به شمارنده‌های واقعی پایگاه داده
- ثبت، مشاهده، جست‌وجو و بایگانی مشتریان
- ثبت/مشاهده/ویرایش/غیرفعال‌سازی محصولات
- ثبت سوابق خرید و ایجاد خودکار یادآور سرویس بر اساس فاصلهٔ زمانی
- مدیریت تیکت‌های پشتیبانی و وضعیت آن‌ها
- مدیریت یادآورهای سرویس
- ساخت کمپین، ارسال کمپین به مشتریانی که `bale_chat_id` دارند و ثبت نتیجه هر پیام
- آزمایش اتصال واقعی بله و ارسال پیام واقعی از پنل
- ثبت پایدار کاربرانی که ربات بله را شروع می‌کنند و ارسال پیام خوشامدگویی
- منوی جداگانه برای کاربران عادی و مدیر بر اساس `BALE_ADMIN_CHAT_ID`
- ثبت تیکت از داخل بله و ارسال آن به چت مدیریت؛ پاسخ مدیر با `/reply`
- پیام همگانی برای کاربران ثبت‌شده و ثبت نتیجه ارسال در کمپین/گزارش پیام
- نمایش آمار، مشتریان، محصولات، خریدها، تیکت‌ها و یادآورها در منوی مدیریتی بله
- گزارش پیام‌ها و گزارش رویدادهای حسابرسی
- ورود و خروج مشتریان از Excel (`.xlsx`)
- مستندات API خودکار در Swagger

## محدودیت‌های مهم

- این نسخه یک MVP است، نه محصول Enterprise نهایی. بات از long polling استفاده می‌کند. هنوز صف پایدار پیام‌رسانی، اجرای زمان‌بندی‌شدهٔ خودکار یادآورها، retry هوشمند، rate limiting سراسری، کنترل پیشرفتهٔ نقش‌ها/مجوزها، مهاجرت‌های Alembic و آزمون امنیتی مستقل ندارد.
- ارسال کمپین در این نسخه مستقیم و ترتیبی انجام می‌شود؛ قبل از ارسال واقعی حتماً فهرست گیرندگان را بررسی کنید. برای کمپین‌های بزرگ از آن استفاده نکنید.
- توکن بات در فایل محلی `.env` خوانده می‌شود؛ این فایل را در GitHub عمومی منتشر نکنید. برای محیط واقعی مدیریت رازها و محدودیت دسترسی باید تقویت شود.
- SQLite برای توسعهٔ محلی است؛ برای استقرار چندکاربره/تولیدی PostgreSQL و مهاجرت پایگاه داده را پیکربندی کنید.
- نسخهٔ فعلی بر اساس محیط توسعه تست می‌شود و نباید «بدون باگ» یا «تولیدآماده» تلقی شود.

## اجرا در Windows PowerShell

در ریشهٔ پوشهٔ `esbot` یک فایل `.env` بسازید از روی `.env.example`:

```
Copy-Item .env.example .env
python -c "import secrets; print(secrets.token_urlsafe(48))"
notepad .env
```

در `.env` مقدار `SECRET_KEY` را با خروجی دستور بالا جایگزین کنید. در PowerShell اول:

```
cd .\backend
python -m venv .venv
Set-ExecutionPolicy -Scope Process -ExecutionPolicy Bypass
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[test]"
python ..\scripts\create_admin.py
python -m uvicorn app.main:app --reload
```

آدرس بک‌اند: `http://127.0.0.1:8000` و مستندات: `http://127.0.0.1:8000/docs`.

در یک PowerShell دوم:

```
cd C:\Path\To\esbot\frontend
npm.cmd install
npm.cmd run dev
```

آدرس فرانت‌اند معمولاً `http://localhost:5173` است. ابتدا با نام کاربری و رمز مدیری که در اسکریپت ساختید وارد شوید.

## Excel مشتریان

فایل ورودی باید `.xlsx` باشد و ردیف اول این ستون‌ها را داشته باشد: `first_name`, `last_name`, `mobile`. ستون‌های `email` و `notes` اختیاری‌اند. شماره موبایل تکراری نادیده گرفته می‌شود.

## آزمون

از پوشهٔ `backend` با محیط مجازی فعال اجرا کنید:

```
pytest -q
```

## امنیت

- فایل `.env`، توکن بله، فایل پایگاه داده و اطلاعات مشتریان را در GitHub عمومی منتشر نکنید.
- در محیط تولید از HTTPS، PostgreSQL، مدیریت امن secretها، backup و پایش سرویس استفاده کنید.

## راه‌اندازی ربات بله

راهنمای کامل تنظیم توکن، پیدا کردن شناسه مدیر، منوی مدیریتی، تیکت و پیام همگانی در فایل [`BALE_BOT_FA.md`](https://github.com/amires996/esbot_bale/blob/main/BALE_BOT_FA.md) است. برای فعال شدن ربات، در فایل `.env` مقدارهای `BALE_BOT_TOKEN` و `BALE_ADMIN_CHAT_ID` را تنظیم کنید و سرور بک‌اند را مجدداً اجرا کنید. اگر این دو مقدار خالی باشند، فقط API وب اجرا می‌شود و polling بات فعال نمی‌شود. انگلیسش کن
